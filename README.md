# MskProd Computing

A free computing revision website for UK students at Key Stage 3, GCSE and A Level,
served at **https://mskprod.org**.

Written to the OCR specifications, with a full explanation, key terms, flashcards,
a ten question knowledge check and five auto marked exam-style questions for every
topic, plus original full length practice papers with mark schemes.

No accounts, no cookies, no adverts, no tracking.

## Building the site

The site is static HTML generated by a single Python script with no third party
dependencies.

```bash
python3 build.py
```

This writes the complete site into `dist/`, including `sitemap.xml`, `robots.txt`,
`search-index.json`, `site.webmanifest`, a `404.html` and the `CNAME` file.

To preview it locally:

```bash
python3 build.py && python3 -m http.server 8000 --directory dist
```

Then open http://localhost:8000

## Pixel Run, the game

`/pixel-run/` is a platformer in ten levels. Pixel runs by herself, and at each of
three obstacles per level the student writes a Python function. If every test
passes she jumps on. Three failed attempts, or giving up, and the obstacle wins:
the solution is shown and the student goes back to the previous level. Python runs
in the student's browser (Pyodide), so nothing they type leaves their device.

Challenges live in `content/pixelrun/bank_a.py` (levels 1 to 5) and `bank_b.py`
(levels 6 to 10), five per level. Expected values are never written down, they are
computed by running the solution.

```python
C("greet", 1, "A polite greeting",
  "The story, one line.",
  "The task. Write `greet(name)`. It returns ...",
  "greet",                                         # the function the student writes
  "def greet(name):\n    pass\n",                  # starter code
  "def greet(name):\n    return 'Hello, ' + name\n",    # the reference solution
  [("Asha",), ("Ben",), ("",)],                    # argument tuples to test with
  ["def greet(name):\n    return 'Hello ' + name\n"],   # plausible mistakes
  ["A nudge.", "`return 'Hello, ' + name`"],       # two hints, the last one the key line
  [loop()])                                        # optional rules
```

`python3 build.py` proves the whole bank before it writes the page and stops if
anything is unsound: every solution must pass its tests and rules, every starter
must fail, and every listed mistake must fail by a test or a rule. Rules can demand
a loop (`loop()`), recursion (`recursive()`), a call to a given function
(`calls("square")`), or forbid names (`forbid(["max"], "why")`, including `"in"`,
`"**"` and `"[::-1]"`). `probes(0, "why")` limits how many items of a list argument
the code may look at, which is how the binary search level refuses a scan from the
front; a long list can be written as `Expr("list(range(0, 2000, 2))")`.

`python3 tools/check_pixelrun.py --mutate` also breaks each solution in small ways
(a `+` becomes a `-`, a `<` becomes `<=`, a line is deleted) and lists the changed
copies that its tests fail to notice. Today those are all equivalent to the
original, such as which of two equal values is returned first.

Progress is stored in the browser under `mskprod:pixelrun`.

## Adding a topic

Every topic is a `Topic` object. Add one to the relevant list in `content/`, then
rebuild. The build script picks it up automatically and adds it to the navigation,
the sitemap and the search index.

```python
Topic(
    slug="my-topic",
    title="My Topic",
    spec="1.2.3",
    icon="i-cpu",
    blurb="One sentence describing it.",
    sections=[Section("Heading", """Mini markup content""")],
    keyterms=[("Term", "Definition")],
    grade="""What separates a top grade answer.""",
    mistakes=["Something students actually get wrong."],
    quiz=[Q("Question?", ["A", "B", "C", "D"], 0, "Why A is right.")],
    exam=[EQ("Explain something.", 3, [MP("Point", ["keyword"])], "Model answer.")],
)
```

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yml`, which builds the site and
publishes `dist/` to GitHub Pages.

### One off setup

1. In the repository, go to **Settings → Pages** and set **Source** to
   **GitHub Actions**.
2. Still under **Settings → Pages**, set the **Custom domain** to `mskprod.org`
   and tick **Enforce HTTPS** once the certificate has been issued.
3. Add the DNS records below at your registrar.

### DNS records for mskprod.org

The domain is registered through Squarespace, which took over Google Domains.
Squarespace's own website builder cannot host this site, but the domain can point
anywhere, so keep the domain where it is and add these records in
**Squarespace → Domains → mskprod.org → DNS Settings**.

For the apex domain, add four **A** records, all with host `@`:

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

Optionally add the matching **AAAA** records for IPv6, also with host `@`:

```
2606:50c0:8000::153
2606:50c0:8001::153
2606:50c0:8002::153
2606:50c0:8003::153
```

For the `www` subdomain, add one **CNAME** record:

```
Host:  www
Value: <your-github-username>.github.io
```

Remove any existing Squarespace parking or forwarding records for `@` and `www`
first, or they will conflict. DNS changes usually take effect within an hour but
can take up to 48 hours to propagate fully.
